## 安装与边界

将该分支放在独立目录 `/home/ubuntu/openarmx_teleop_vr_v5`，按其 `scripts/setup_v5_mink_env.sh` 建立独立Mink环境。
不要覆盖原厂SDK、V4环境或运行中的采集目录。源版本变化必须重新审核，不能跳过哈希。

新增选择：

```bash
export DAGGER_TELEOP_BACKEND=v5
export DAGGER_V5_SOURCE_ROOT=/home/ubuntu/openarmx_teleop_vr_v5
export ROBOT_ID=340 ROBOT_TYPE=autolife_s3 DAGGER_ROBOT_PROFILE=s3_v3_1
```

DAgger在`.runtime/v5-*`建立经校验的私有副本。为兼容现有监督器、网页、录制和输出回执，副本保留旧的`openarmx_teleop_vr_306_v4`模块/话题名称；实际求解器为V5 Mink，原始V5映射/求解文件不变，只替换兼容命名。界面日志中的306/V4不是目标机器人编号，硬件话题后缀由`ROBOT_ID`和ROS域确定。

补丁增加：模型/专家epoch隔离、即时接管重锚、异步IK提交前复核、输出来源回执、专家状态下才允许腰部跟随、任务快照复位、未使能退出零命令。使用V5原生配套简化URDF/SRDF，不拿完整SDK网格和另一套碰撞排除表混用。21个受控关节的轴、坐标变换、上下限与340实际SDK逐项一致；这个静态检查不能代替实机碰撞验收。

V5手柄闭合百分比保持上游默认90%（逻辑角325°），配置按当前机器人编号独立保存，不读写345的设置。模型端使用下述binary330规则，客户端不修改proposal中的动作。

### 现场测试顺序

1. 结束正在运行的普通/单人/子任务采集，等待所有保存落盘；让原厂遥操、导航及其他推理正常释放控制权。冲突检查不通过时处理当前控制端，不能跳过检查或重启ARM绕过。
2. 打开桌面“云蝶DAgger启动器”，确认340 / V5，保持默认模型、任务、姿态与深度。点“选择 checkpoint…”刷新，核实当前模型就绪后关闭。首轮先沿用020000，暂不换模型。
3. 备注填 `v5_acceptance`。勾选“允许真机控制”。先在**未启动采集服务**时点“全身复位”，检查双臂、头腰和双夹爪到位，界面确认完成。这验证独立复位，不需要头显。
4. 点击“启动采集服务”。就绪后仍应为“待开始/未录制”，机器人不因打开网页自动执行模型。头显进入 `https://192.168.8.59:8447`；人工接管才需要头显。
5. 点“开始推理 + 录制”，模型自主完成后点“确认任务成功并保存”。等待落盘/计数加一，应为**自主成功**；后台排队尚不算保存成功。
6. 点“全身复位”再开始一条，按单侧Grip接管，小幅平移/旋转并缓慢开合扳机。检查单侧接管、跟手、夹爪、腰部仅接管后跟随；松Grip保持，重新握持重建基准，不自动交还模型。完成后保存，计数应为**纠错成功**，数据保留纠错掩码。
7. 再开一条点“任务失败并保存”，核实失败标签和落盘反馈。另开一条点“丢弃本条”，核实丢弃计数、已保存条数不增加、机器人不自动复位。
8. 点击“封口并继续 F”，等待队列完成，服务应保持可用，可以复位并开始下一条。点击“退出采集 Q”，等后台清理结束后关窗口；退出前先处理本条，未确认条目会丢弃。
9. 验证急停：在已开始的低风险测试中点击红色“急停（锁定）”，确认动作停止与ESTOP。若接口不可达会提示实体急停，不应假报成功。
10. 其余流程通过后再停止采集服务，选另一个**训练任务和S3适用性已确认**的checkpoint并应用，等待实际模型名称就绪。修改对应任务与姿态后重测一小条；列表中的接口兼容不代表S3运动效果已验收。

按钮对应关系：

| 功能 | 启动器 | 头显 |
|---|---|---|
| 开始推理并录制 | 开始推理 + 录制 / Shift+A | A |
| 成功并保存 | 确认任务成功并保存 / Shift+B | B |
| 失败并保存 | 任务失败并保存 / Shift+K | Y长按1秒 |

启动器快捷键在文本输入框内不触发。界面按钮不依赖手柄连接；编辑框在本轮服务运行时锁定。
保存/丢弃不隐含复位，下一条前明确复位。真实计数按落盘结果更新，含自主成功、纠错成功、失败及丢弃反馈。

### 模型管理边界与回退

S2仍使用8777及原来的管理密钥。S3使用8783和独立受限密钥，只允许模型列表/切换；不能执行任意shell。
`dagger/s3_checkpoint_control.py` 安装于Thor的 `/home/wayne/collector_v5_management_20261106`。
`dagger/s3_server_source.json` 固定原始native服务来源，`dagger/s3_server.patch`只替换模型验证和名称，保留原推理、CPU加载、binary330、proposal digest、ACK和幂等receipt实现。
新服务代码仅在下次用户主动切换checkpoint时加载，现运行的020000服务未重启。新上传模型须位于Thor的`models`目录，包含完整模型/processor与相同21维合同，刷新即可发现；选择前仍须确认训练机器人和任务。
切换会先申请服务端reload租约，拒绝活动会话，只结束核验过的S3容器。新服务退出/缺失时可尝试恢复原模型；服务仍运行但状态不明时保留现场并报错，不强制回滚中断它。

回退启动器：退出新服务后，将上述备份目录的`autolife-dagger-launcher`和桌面文件恢复原位置；本次未覆盖正式采集仓库或修改原厂服务。模型切换回原模型仍通过启动器完成，切换不改S2的baseline链接。
