# 集成式电脑采集播报（340待现场验收）

采集启动时自动提供播报网页，声音由打开网页的电脑发出。无需下载脚本、安装程序或使用OCR。网页只接收当前采集的状态确认，没有机器人控制接口。

## 使用

1. 在340照常运行原来的集合版启动命令。机器人扬声器故障时，将`VR_SPEECH=1`改为`VR_SPEECH=0`；电脑播报仍然可用。
2. 终端会打印“电脑播报”链接，在电脑Chrome/Edge中打开完整链接（包括`#`后面的内容）。340通常选`192.168.8.59`开头的地址，端口随本次采集自动分配。电脑需要能访问机器人局域网。
3. 点击一次“开启播报”，确认页面已连接，再开始录制。声音使用电脑现有中文语音，浏览器需要这一次点击才能开启音频。若系统没有可用中文声音，页面会明确报错，不会假装已播报。
4. 可以切回采集终端，但保持网页打开。关闭网页或点击“停止播报”仅停止电脑声音，不影响采集和遥操。
5. F封口后网页继续跟随下一条；Q正常退出采集时网页服务自动结束。下次启动采集使用新链接。

普通、单人、子任务与DAgger的内部录制器均经过公共启动流程。DAgger由启动器隐藏后台终端时，可在其录制启动日志中找到“电脑播报”链接；DAgger控制器全部内部状态不在播报范围内。

可选开关：`PC_SPEECH_WEB=0`关闭网页服务，默认1。网页启动失败只会提醒，不阻止采集。`VR_DEBUG_INPUT=1`临时恢复手柄输入调试；默认0保留采集确认、错误和断连提示，不再刷手柄监听。

## 播报规则

- 单人/子任务直接跟随VR采集日志：三、二、一、开始、每次子任务标记、保存、丢弃、封口和异常。重复“下一步”按不同事件逐条播报，不按相似文字去重，也没有三个子任务的限制。
- 普通/DAgger读取录制器发布的实际回执；后台排队与最终落盘分别反馈。标注不完整保留提醒，“后台保存中”不等于“已保存”。
- 每次连接从当前状态开始，不补播历史消息。断线、日志截断或事件遗漏会停止并提示，核对终端后重新开启，不自动跟随其他任务。
- Q退出时VR状态源可能先退出，网页会提醒检查终端最终保存结果，不能用网页结束当作保存完成。
- 音频在电脑异步排队，文字不会因为重复或超过固定数量而被静默丢弃。快速操作下声音可能落后，以终端/头显和实际落盘回执为准。
- 机器人端只用系统Python读取既有文本日志并提供只读网页，不新增ROS订阅、相机访问或控制命令。使用浏览器本机中文声音，不调用云端语音服务。
- 网页按本次随机链接授权；不要分享完整链接。采集退出即停止服务，不保留新的常驻服务。

## 340现场验证

1. 正常退出旧采集后重新启动；确认手柄动作不再刷`[VR input]`，采集状态仍显示。
2. 打开终端链接，开启播报后测试A倒计时。使用至少5个子任务，逐次标记，第四次也应有反馈；最后一次转为保存流程。
3. 连录两条，确认两次最终“第N条已保存”都能听见；核对终端计数和数据落盘。后台排队提示不能算保存完成。
4. 测试Y丢弃、F封口后继续，最后Q退出。关闭播报网页时采集应继续正常运行，重新开启不补播旧记录。
5. 普通模式测试Enter/S/D/F/Q；DAgger测试开始、成功保存、失败保存、丢弃。实际电脑声音及四模式真机操作仍需现场验收。

## 兼容与回滚

原电脑PowerShell工具保留为可选后备：`tools/start_pc_speech.bat`与`tools/collector_pc_speech.ps1`。默认网页方案不需要它，也不需要在电脑配置SSH。旧OCR工具应关闭以免重复播报。原机器人语音保持可选，扬声器恢复后可设置`VR_SPEECH=1`。

只停用网页可设`PC_SPEECH_WEB=0`，不修改采集、保存、控制和相机逻辑。部署采用备份与原子替换，下次启动生效，不热替换当前Python进程。
