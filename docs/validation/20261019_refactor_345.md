# 2026-10-19 Collector重构与345验证

## 范围与结论

在345上完成5条独立的真实传感器静止录制、全部视频解码、LeRobot v3读回及一次EEF离线转换。
四个标准关节/深度组合和额外EEF组合均通过；合计3334帧、0次invalid、0次图像FIFO溢出。
这是短时静止采集验收，不是长时间稳定性、运动质量或DAgger闭环任务成功率测试。

本次未发送运动、使能、复位指令，未停止或重启原厂手臂/视觉服务，未修改同事原始遥操作代码。
keyboard、vr、subtask、dagger控制链分别有回归/隔离ROS证据；不能把后者写成手柄实操验收。

## 修改范围

- 把参数、校验提取到纯标准库的`recorder_config.py`；`launcher_help.py`复用定义生成启动器帮助。
  全量/单参数帮助无需加载ROS、Torch或LeRobot，保留原有参数入口和数据契约。
- 启动器去除重复帮助与编码参数分支；新增启动阶段会话锁、开关/目录名校验。
  DDS按显式Collector配置、已有环境、默认回环配置的顺序选择。
- 普通模式正常Q/EOF/中断会等待录制器完成保存，删除固定30秒后终止写入者的行为。
  编码未结束时不清除活动会话文件；DAgger继续使用其独立安全关闭逻辑。
- FIFO拒绝普通文件、符号链接、非法命令、换行注入和非原子长消息；无效超时在发命令前拒绝。
  PID必须为正数，未知回执不自动重试。
- 同步日志写入失败使当前episode失效；开始和提交前检查缓冲写入，失败状态保持到重启。
  后续诊断失败不撤销已提交数据。
- SHM2校验slot容量/偏移及实际文件边界，防止损坏metadata导致异常大内存分配。
  保留active-slot读取、手部JPEG路径、时间戳去重及原有同步阈值。
- 正常帧路径不再为未发生的状态匹配错误计算诊断范围；超大整数时间戳不会使回调溢出崩溃。
- DAgger先验证机器人profile，再创建ROS节点/后台线程，避免错误配置留下半初始化进程。
- 移除先前要求删除的S3临时推理预览及专属测试；保留必要的环境适配、型号校验、EEF与来源保护。
- 重写README和中英文INSTRUCTION；README先介绍参数，再按模式区分遥操作版本、命令和限制。
  保留必要回归、故障注入测试及审计快照，不把它们当作临时文件删除。

没有修改其他训练/部署模块、已有用户数据、V4控制核心和固定资源哈希。
没有通过增大同步误差、丢帧、减小采集FPS来获得通过结果。

## 真实采集结果

| 独立数据目录 | 内容 | state/action维数 | 帧数 | 参考时间戳实际FPS | 最大软件时间差 |
|---|---|---|---:|---:|---:|
| arms_rgb | 手臂/夹爪 + RGB | 16/16 | 531 | 30.003 | 19.41 ms |
| arms_rgbd | 手臂/夹爪 + RGB + 深度 | 16/16 | 553 | 30.005 | 20.53 ms |
| full_rgb | 全量关节 + RGB | 23/23 | 746 | 30.005 | 20.09 ms |
| full_rgbd | 全量关节 + RGB + 深度 | 23/23 | 379 | 29.999 | 27.18 ms |
| full_eef_rgbd | 全量关节 + EEF state/action + RGB + 深度 | 37/37 | 1125 | 30.004 | 21.07 ms |

最大差值按已接收帧的`sync_deltas_ms`绝对值统计，包含状态插值两端、action和图像。
27.18 ms来自`full_rgbd`的后侧关节样本，不是相机曝光延迟，也不是单帧代码执行耗时。
全体参考帧间隔范围约30.99至37.13 ms。启动阶段各有1至3个等待tick，不是已录制数据跳帧。
所有episode的`episodes_invalidated=0`、`image_buffer_overflows=0`。

每组检查包括：

- Parquet行数与meta帧数一致，state/action维度正确且全部数值有限。
- 每个RGB/H.265深度视频逐帧完整解码，解码帧数等于对应episode帧数。
- `LeRobotDataset(..., video_backend="pyav")`读回首、中、末帧，图像/深度维度和值域有效。
- 其中4组使用S保存后Q退出；`full_rgbd`专门在仍有待保存数据时按Q。

`full_rgbd`从`quit_requested`至`episode_saved`为38.58秒，正常完成379帧编码与事务提交。
该例直接覆盖了旧30秒关闭期限可能中断编码的风险。
