# Collector Design

See [README](README.md) for usage and parameters, [中文](INSTRUCTION_zh.md) for the Chinese design.

## Ownership and Modules

- Launcher/config modules validate modes, environment, session ownership and correlated commands.
- record_lerobot_official.py owns ROS sampling, FIFO alignment, episode state and publication coordination.
- robot_schema.py/eef_schema.py own joint order, physical mapping, pose units, interpolation and schema checks.
- shm_camera.py/jpeg_decoding.py/time_sync.py own consistent SHM snapshots, decoding and alignment.
- camera_session.py optionally manages explicitly configured camera sessions; it may restart vision on transition.
- dagger/capture_image_writer.py is the bounded asynchronous PNG/TIFF writer shared by all four modes.
- episode_storage.py owns disk budgets, asynchronous diagnostic logs, publication journals and rollback.
- background_saves.py owns the durable bounded outbox and single low-priority encoder process.
- first_frames.py stages original RGB frame zero; extract_first_frames.py backfills from v3 video offsets.
- video_encoding.py shares startup hardware probes, full readback and writer-local adaptation across save modes.
- VR/subtask modules own buttons, feedback, exclusive-end boundaries and request acknowledgements.
- dagger/ and dagger_labels.py own reviewed incremental control, authority, Thor integration and expert masks.
- convert_dataset.py projects state/action independently into a new dataset.
- scripts/setup_collector_env.py installs/checks an isolated environment without controlling hardware.

Keep tests, inspected teleop snapshots, patches and SOURCE.json hashes. They are dependencies or provenance,
not temporary artifacts. Historical process reports live in Git history, not the operational guide.

## Startup and Data Contract

Keyboard, VR and subtask use factory teleoperation; DAgger uses a reviewed incremental-control copy.
Wait for complete state before JPEG initialization and camera warmup. Enabling camera_session.json may
change reviewed vision configuration and restart vision; unconfigured robots retain existing behavior.
The environment installer does not restart services or enable motors.
Session, dataset, motion and request locks have distinct responsibilities.

Joint order is left arm 7, right arm 7, two grippers, optional head 3, then upper waist 2 OR full waist/legs 4.
Base is 16 dimensions, head plus upper waist 21, full configuration 23. Waist modes are mutually exclusive.
Regular status_target reads body targets from telemetry and measured grippers. DAgger requires joint
command publications plus provenance; it cannot substitute measured state for missing commands.

WITH_EEF_STATE/ACTION each append left XYZ+XYZW and right XYZ+XYZW (14 values, no grippers).
Units are robot-frame metres and unit quaternions. State uses linear XYZ interpolation and shortest-arc
SLERP; action holds a causal target. Missing data is rejected, never zero-filled or inferred with FK.
EEF action expert masks stay zero: joint provenance does not establish independent EEF provenance.
Resume validates FPS, cameras, joint/EEF layout, depth, subtasks and DAgger fields; width equality is insufficient.

## Image and Time Path

Vision produces SHM; Collector reads it. Hands use JPEG only, with no direct-BGR fallback.
ShmCameraReader reuses read-only descriptors, checks current file sizes and reopens replaced producers.
It uses pread, not mmap, so producer truncation cannot cause a mapping SIGBUS. Legacy metadata and SHM2 are supported.
It reads the published active slot, not an SDK sequential history. Metadata is checked around copying.
Each poll copies streams before decoding; unchanged timestamps do not re-enter FIFOs.
This does not prove that every frame generated by a camera was observed.

JPEG_DECODER=auto prefers nvJPEG, falling back to OpenCV only during initialization.
nvjpeg is strict; opencv forces CPU. GPU outputs are owned CPU RGB HWC arrays. Raw depth bypasses JPEG.
Runtime GPU failure invalidates the active episode and stops recording; it never silently changes backend.

Image FIFO defaults to 16 per camera; signal history defaults to 64. Consume reference frames in order,
match nearest peer images, interpolate bounded state brackets and hold only causal action targets.
The matching wait is max(sync tolerance, state interpolation span), not a per-frame compute deadline.
Stalls, stale input, interval errors, alignment failures and active FIFO overflow invalidate the entire
episode. No fabricated frames hide failures. Receive-time fallback is not hardware exposure synchronization.

## Storage and Recovery

The image queue defaults to 64 jobs/256 MiB. Depth retains TIFF and native quantization.
Disk budgets refresh asynchronously; stale checks, exhausted space and image/log failures stop admission.
Diagnostic JSON serialization runs in one bounded worker; explicit barriers precede start/publication receipts.

BACKGROUND_SAVE=1 is the default. Stop writes for the current episode, persist arrays, relative image paths,
labels and codec configuration under .collector-queue/<job>, then acknowledge save_queued.
This means durable staging, not completed publication. At most two episodes wait for one low-priority encoder;
new capture may overlap encoding. A full queue rejects new capture. F seals and Q exits only after draining.
Failures retain raw jobs, block new episodes and invalidate any active unfinished capture.
Restart reconciles publication markers instead of duplicating saves.

BACKGROUND_SAVE=0 saves synchronously and is rejected while unfinished background jobs exist.
Both modes use the same first-frame export, codec selection, annotations and EpisodeStore transaction.
Original frame-zero PNGs are hardlinked to first_frame/{head,left,right}_frame with names such as
head_episode_00000.png. They commit/roll back with the episode, never sample current live images.

VIDEO_ACCELERATOR=cpu does not probe NVENC. auto probes NVENC then VAAPI at startup; explicit requests
fail if unavailable. Runtime failures never retry on CPU. Hardware video affects RGB only, not depth.
Startup probes check color/range; each saved output is fully decoded to validate frame count, size, FPS
and timestamps. Codec receipts live under annotations/video_encoding. Background jobs replay their
stored configuration, not current environment defaults.

EpisodeStore writes a fresh private workspace, never appending into historical data/videos. It fsyncs
staged output and a journal, publishes without overwriting, swaps metadata, then marks committed.
Prepared work rolls back; committed work only cleans up. Raw queue cleanup failure must not turn an
already committed episode into an apparent failed save. Do not delete live queues, locks or recovery files.

## Labels and Controls

Consult README for current bindings. Factory VR/subtask face buttons require both Grips; DAgger does not.
Grip immediately transfers authority to the human. Subtask short B marks an exclusive-end boundary;
long B saves early, leaving unconfirmed tails -1/needs_review. VR_SUBTASK_B_REARM_SEC requires a continuous
release after acknowledgement, preventing duplicate marks without pausing capture.

DAgger outcomes are separate from expert masks: B saves success, short Y discards, one-second Y saves failure;
terminal K saves failure. F only seals, Q exits. X only resets and refuses busy, pending or uncertain states.
The scalar training mask remains the body/gripper AND; per-action masks preserve independent provenance.
Held old targets never become fresh expert actions; model-only frames have zero expert mask.
A successful save does not prove physical task completion.

Offline conversion projects state/action, masks and statistics consistently, retaining first frames and
annotations. Backfill uses v3 per-episode video offsets, never shared-MP4 frame zero for every episode.
Offline tools require exclusive access and do not invent historical labels.
